# SyncView를 선택할 이유와 현재 한계

검토일: 2026-09-22. 경쟁 도구의 공개 문서와 SyncView의 코드·[실측 기록](VALIDATION.md)을 비교했다. 경쟁 제품을 같은 장비에서 실행한 성능·사용성 비교나 외부 사용자 조사는 수행하지 않았다.

## 판단

**여러 로컬 클립을 그리드로 비교하고, 설명을 붙인 MP4로 전달하는 작업에는 선택할 이유가 있다.** 영상 창을 따로 조작하던 사람이 공통 재생·오프셋·이름표·프로젝트 저장·합성 export를 한 흐름으로 사용할 수 있다. 이것은 작업 흐름에 관한 가치 가설이며, 시장 수요나 시간 절감 효과가 이미 검증됐다는 뜻은 아니다.

우선 대상으로 볼 수 있는 작업은 모델·필터·렌더링 시안의 정성 비교, 여러 촬영 테이크의 타이밍 비교, 회의·보고용 비교 영상 제작이다. 픽셀 단위 화질 판정, 정밀 스포츠 계측, 법적 증거 분석 같은 용도에 필요한 정확성을 주장하지 않는다.

## 이미 존재하는 대안

| 도구 | 공개 문서에서 확인한 강점 | SyncView의 선택 기준 |
|---|---|---|
| [pixop/video-compare](https://github.com/pixop/video-compare) | 동기 A/B, 확대·차영상·스코프·프레임 이동, 기준 영상과 여러 후보 전환 | 정밀 A/B 분석보다 여러 클립을 동시에 배치하고 문구를 붙인 결과물을 만드는 작업에 초점 |
| [vMyth/video-compare](https://github.com/vMyth/video-compare) | 두 영상 동기 비교, 트리밍, 오디오 선택, 합성 export | 동기 비교와 export 자체는 독창적이지 않다. 가변 그리드·영상별 이름표·오프셋·프로젝트 복원이 선택 이유 |
| [DualView](https://github.com/gokayfem/dualview) | A/B 비교, 그리드·차영상·여러 분석 모드 및 export를 문서화 | 그리드도 독점 기능이 아니다. Windows에서 영상 비교 자료를 만드는 좁은 흐름과 한국어 UI에 집중 |
| [OBS Studio](https://obsproject.com/kb/sources-guide) | 영상·텍스트 소스의 자유로운 장면 구성과 녹화 | SyncView는 로컬 파일의 공통 시간축과 파일 전체 합성 export에 초점. OBS의 유연성·생태계보다 우월하다고 주장하지 않음 |

## 사용자가 얻는 결과

- **함께 볼 수 있음:** 여러 클립을 한 재생바로 탐색하고 시작 시각은 오프셋으로 조정한다. 오프셋은 수동이며 자동 음성 동기화는 없다.
- **설명을 남길 수 있음:** 이름표에 파일명·타임코드·설정명을 붙이고 그 배치를 MP4에 포함한다.
- **다시 편집할 수 있음:** 순서·배치·오프셋·디자인을 프로젝트로 저장한다. 원본 미디어는 별도로 보관해야 한다.
- **로컬에서 처리함:** 앱의 비교·export에 계정이나 클라우드 업로드가 필요 없다. 최초 의존성 설치·다운로드는 별개다.

## 채택을 막는 요소

현재 GitHub 제공물은 소스다. Python·FFmpeg 설치는 일반 사용자에게 진입 장벽이며, 실행 파일을 만들 수 있다는 것과 검증된 바이너리를 바로 내려받을 수 있다는 것은 다르다. 한국어·영어 즉시 전환과 두 언어의 도움말을 추가했고, 설치가 필요 없는 포터블 ZIP 생성 경로를 마련했다. 공개 다운로드 제공에는 외부 라이선스 자료 준비가 남아 있다.

기준 장비의 기본 하드웨어 경로는 9개 미리보기에서 불안정했고 소프트웨어 옵션에서만 목표를 만족했다. 고해상도 장시간 재생·다양한 장비의 결과는 아직 부족하다. 원본과 출력의 픽셀 일치, 프레임 단위 동기 보장, 객관적 화질 점수, 자동 동기화, 범위 트리밍, 오디오 믹싱 기능도 약속하지 않는다.

## README와 다음 검증

README의 첫 약속은 **“비교는 한 화면에서. 공유는 하나의 MP4로.”**로 정한다. 실제 합성 영상으로 실행한 앱 화면, 명확한 설치 경로와 한계를 함께 제시한다. 가장 빠르다·유일하다·완벽히 동기화된다는 문구는 사용하지 않는다.

다음 제품 검증은 해당 작업을 하는 외부 사용자에게 영상 추가부터 비교 MP4 저장까지 직접 해보게 하는 것이다. 기존 도구와 걸린 시간·실패 지점·재사용 의사를 비교하고, 반복 사용이 확인되면 바이너리 배포 준비·번역 사용성·기본 디코딩 안정성을 우선 개선한다.
