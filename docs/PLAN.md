# 동영상 멀티뷰 데스크톱 도구 기획 및 구현 계획

## 1. 목표와 기술 선택

### 목적과 산출물

여러 로컬 동영상을 그리드로 비교하고, 테두리·영상별 이름표를 편집하여 하나의 합성 영상으로 저장한다. 사내·개인용 Windows 데스크톱 도구로 만들며 서버나 계정 없이 사용한다.

최종 산출물은 다음과 같다.

- 설치 없이 실행하는 Windows x64 단일 EXE.
- 화면 디자인과 시간 보정이 반영된 합성 MP4.
- 같은 편집 상태를 다시 열 수 있는 JSON 프로젝트 파일.

현재 SyncView 앱, 합성 영상 기반 테스트, 패키지 설정과 단일 EXE 빌드 spec이 구현되어 있다. 이 문서는 기능과 모듈 경계의 기준이며, 사용 방법은 [README](../README.md), 실제 확인한 결과와 남은 검증 범위는 [검증 기록](VALIDATION.md)을 따른다. 개인 테스트 영상과 빌드 결과물은 Git에 포함하지 않는다.

### 기술 스택

| 항목 | 선택 | 역할과 이유 |
|---|---|---|
| 언어 | Python 3.12, 64비트 | UI와 제어 코드를 간결하게 작성한다. |
| GUI | PySide6 / Qt Widgets | 파일 선택, 설정 패널, 타임라인을 갖춘 데스크톱 UI를 구성한다. |
| 미리보기 | QMediaPlayer / QVideoSink | 영상을 재생하고 받은 프레임을 합성 캔버스에 그린다. |
| 영상 처리 | FFprobe / FFmpeg | 메타데이터 분석과 최종 MP4 합성을 담당한다. |
| 패키징 | PyInstaller | `onefile`, `windowed` 설정으로 콘솔 없는 단일 EXE를 만든다. |
| 검증·스타일 | pytest / pytest-qt / Ruff | 계산·UI·통합 테스트와 코드 스타일을 관리한다. |
| 프로젝트 저장 | 버전이 명시된 JSON | 원본 참조와 편집 설정을 저장한다. |

Python은 상태와 작업을 조정하고, 실제 영상 디코딩·인코딩은 Qt와 FFmpeg에 맡긴다. QVideoSink는 프레임 단위 접근과 그리기를 지원한다. [Qt QVideoSink 문서](https://doc.qt.io/qtforpython-6/PySide6/QtMultimedia/QVideoSink.html)

초기 구현에서 검증한 의존성 버전을 고정하고, 빌드에 포함하는 FFmpeg·FFprobe의 버전과 출처도 기록한다.

### 첫 버전 범위

Windows x64와 로컬 파일을 지원한다. UI는 한국어·영어를 선택하며 첫 실행은 시스템의 UI 언어를 따른다(그 외 언어는 영어). PNG export, 자유 배치 편집, 다중 오디오 혼합, 프레임 단위 분석, 자동 업데이트는 후속 범위다. 영상 개수는 가변적으로 처리하되 첫 버전의 성능 검증 범위는 2~9개로 한다. 임의의 해상도와 개수에서 실시간 성능을 보장한다는 의미는 아니다.

## 2. 사용자 기능과 기본 동작

### 화면과 파일 관리

- 왼쪽: 영상 목록, 추가·삭제·순서 변경, 선택 상태.
- 중앙: 최종 출력 비율을 유지하는 합성 미리보기.
- 오른쪽: 그리드·배경·테두리 설정과 선택 영상의 이름표·오프셋 설정.
- 아래: 전체 재생·일시정지, 공통 탐색바, 현재 시각·전체 길이, 오디오 선택.
- 파일 선택과 드래그앤드롭으로 여러 영상을 추가한다. 분석 중 상태와 읽기 실패 원인을 표시한다.
- 특정 파일명, 두 개의 입력, 고정된 원본 해상도를 전제로 동작하지 않는다.

### 그리드와 디자인

영상 수에 맞게 자동 배치하고 열 수를 직접 지정할 수 있게 한다. 행 수는 영상 수와 열 수로 계산하며 남는 셀은 배경색으로 표시한다. 영상은 원본 비율을 유지하여 셀 안에 맞추고 남는 공간은 배경색으로 채운다. 회전 정보와 표시 비율을 배치에 반영한다.

편집 항목은 다음과 같다.

| 대상 | 설정 |
|---|---|
| 캔버스 | 출력 크기, 배경색, 외곽 여백 |
| 그리드 | 자동 배치 또는 열 수 지정, 셀 간격 |
| 테두리 | 전체 표시 여부, 두께, 색상 |
| 영상별 이름표 | 문구, 표시 여부, 네 모서리 중 위치, 글자 크기·색상, 배경색 |

이름표의 초기 문구는 확장자를 제외한 파일명이다. 셀 좌표와 장식 크기는 출력 캔버스 기준으로 계산하며 미리보기 창 크기에 맞춰 함께 축소·확대한다.

### 공통 타임라인과 동기 재생

전체 재생·일시정지·탐색을 제공하고 영상별 시작 오프셋을 밀리초로 저장한다.

```text
원본 시각 = 공통 시각 − 영상별 오프셋
영상별 종료 시각 = 오프셋 + 원본 길이
전체 길이 = max(0, 각 영상의 종료 시각)
```

- 양수 오프셋은 영상을 늦게 시작한다. 예를 들어 `+2000ms`이면 공통 시각 2초부터 원본 0초를 표시한다.
- 음수 오프셋은 원본 앞부분을 건너뛴다. `-2000ms`이면 공통 시각 0초에 원본 2초를 표시한다.
- 시작 전에는 배경색을 표시하고, 끝난 영상은 마지막 프레임을 유지한다.
- 모든 영상은 공통 시계를 따르고 재생 위치 차이를 주기적으로 보정한다. 탐색 시에도 같은 시간 계산을 적용한다.
- 가장 늦게 끝나는 영상을 기준으로 전체 재생과 export를 종료한다. 재생 가능한 구간이 없는 프로젝트는 재생·export 전에 안내한다.
- 일반 비교용 동기를 목표로 한다. 안정 재생 시 동기 오차 100ms 이내를 기준 장비에서 측정하며, 프레임 단위 정합은 약속하지 않는다.

### 오디오

기본은 무음이다. 사용자가 영상 하나를 선택하면 그 영상의 오디오만 재생하고 export한다. 영상 오프셋을 오디오에도 적용하며, 선택 영상의 시작 전·종료 후 구간은 무음으로 채운다. 오디오 트랙이 없는 영상은 무음으로 처리한다.

### 프로젝트 저장과 열기

프로젝트에는 스키마 버전, 원본 경로, 영상 순서·오프셋·이름표, 그리드·디자인, 출력 설정, 오디오 선택을 저장한다. 원본 영상은 프로젝트에 복사하거나 수정하지 않는다.

프로젝트 파일 기준 상대경로를 우선 사용하고 상대경로로 표현할 수 없는 위치는 절대경로를 사용한다. 저장 위치가 바뀌면 경로를 다시 계산한다. 원본이 없으면 해당 항목을 식별하여 다시 연결할 수 있게 하고, 저장·열기 후 편집 상태를 복원한다. 지원하지 않는 스키마 버전은 명확한 오류로 안내한다.

### MP4 export

| 항목 | 기본 동작 |
|---|---|
| 형식 | MP4, H.264, `yuv420p` |
| 크기 | 기본 1920×1080, 사용자 지정 지원 |
| 프레임률 | 기본 30fps, 24/30/60fps 선택 |
| 길이 | 오프셋이 반영된 전체 타임라인 |
| 오디오 | 기본 없음, 선택 시 AAC |
| 진행 상태 | 진행률 표시, 취소 가능 |

출력 크기는 인코더가 허용하는 양의 짝수 크기로 검증한다. 원본 FPS가 달라도 공통 출력 시간축으로 합성한다. 비율 유지 확대·축소, 여백, 시간 보정, 마지막 프레임 연장에는 FFmpeg 필터를 사용한다. [FFmpeg 필터 문서](https://ffmpeg.org/ffmpeg-filters.html)

렌더링은 출력 위치의 임시 파일에서 수행하고 성공한 경우에만 최종 파일로 확정한다. 기존 파일 교체는 사용자 확인을 받으며 취소·실패 시 원본과 기존 결과물을 보존한다. 출력 경로가 입력 영상과 같으면 거부한다.

## 3. 모듈 구조와 구현 규칙

### 책임 분리

현재 구조는 다음과 같다. 새 기능은 해당 책임을 가진 모듈에 추가한다.

```text
src/videos_multi_view/
  __main__.py       # 실행 진입점과 의존성 연결
  core/            # 데이터 모델, 시간·레이아웃 계산
  media/           # 영상 분석·재생·export
  application/     # 사용자 명령, 프로젝트 입출력, 작업 상태
  ui/              # 창·패널·미리보기 캔버스
  assets/          # 패키지와 EXE가 공유하는 로고
tests/             # 단위·UI·통합 테스트
test_assets/       # 기존 로컬 검증 영상
docs/              # 기획·기술 문서
scripts/           # FFmpeg 준비와 성능 측정
```

| 모듈 | 책임 | 경계 |
|---|---|---|
| `core` | 프로젝트·영상·레이아웃·출력 설정 dataclass, 시간 계산, 셀 좌표 계산 | Qt, 파일, 프로세스 입출력에 의존하지 않는다. |
| `media` | FFprobe 분석, Qt 플레이어 관리, 동기 제어, FFmpeg 인자 생성·실행 | UI 위젯에 의존하지 않는다. |
| `application` | UI 명령을 처리하고 프로젝트 저장·열기 및 작업 상태를 조정 | 파일 입출력과 기능 연결을 담당한다. |
| `ui` | 사용자 입력, 설정 표시, 미리보기와 공통 장식 그리기 | 시간·배치 계산과 FFmpeg 명령 생성을 중복하지 않는다. |

데이터 흐름은 `사용자 입력 → application → core 상태 변경 → 미리보기 갱신`을 기본으로 한다. 파일 추가 시 비동기로 메타데이터를 확인한 뒤 프로젝트에 반영한다. export는 시작 시점의 프로젝트 상태를 기준으로 수행하여 도중의 UI 변경과 섞이지 않게 한다.

### 미리보기와 export의 일치

- 레이아웃 계산 결과를 두 경로에서 공유한다. 그리드와 영상 영역을 각각 다시 계산하지 않는다.
- 미리보기는 QVideoSink에서 받은 최신 프레임을 공통 좌표에 그린다.
- 테두리와 이름표는 위젯과 분리된 공통 Qt 렌더러로 그린다.
- 정적 글꼴 측정·이름표 이미지·테두리 경로는 설정 변경 시 갱신한다. 긴 이름표는 셀 내부에서 말줄임한다.
- export에서는 정적 장식을 PNG 한 장으로 합성한다. `{timecode}`가 있으면 작업 스레드에서 같은 렌더러로 시간별 RGBA 프레임을 만들어 FFmpeg 파이프로 전달한다. 현재 프레임과 운영체제 파이프 버퍼만 유지한다.
- 공통 렌더러에는 위젯 의존성이 없으며 영상 디코딩이나 export 프로세스를 실행하지 않는다. 미리보기와 export 작업 스레드가 직접 공유한다.
- 한글 이름표와 글꼴을 미리보기·export에서 동일하게 처리한다. 영상 압축에 따른 픽셀 차이는 허용하되 배치·문구는 일치해야 한다.

### 실행과 자원 관리

분석과 export는 비동기로 처리한다. 분석은 최대 두 개씩 실행하고 선택 순서대로 반영한다. 중복 요청을 제거하며 프로젝트 교체·종료 후 이전 응답은 무시한다. UI 스레드에서 작업 완료를 기다리지 않으며 외부 프로세스는 인자 배열로 실행한다. 취소 시 프로세스 종료를 확인한 후 임시 파일을 정리한다. 한글·공백 경로를 지원한다.

재생 시계는 기준 위치와 단조 시계의 경과 시간으로 계산한다. 디자인 변경은 플레이어를 재시작하지 않고, 원본 경로나 시간 설정이 바뀔 때만 재연결·탐색한다. FPS·인코더 변경은 즉시 프로젝트와 변경 상태에 반영한다. 프로젝트 JSON 버전은 1을 유지한다.

새 원본의 로딩 완료는 해당 플레이어만 탐색한다. 자동 시간 보정에는 최소 250ms 간격을 두어 디코더가 진행 중인 탐색을 마칠 시간을 확보하며, 사용자 탐색은 즉시 적용한다. 프레임 수신은 Qt 슬롯을 통해 UI 스레드에서 처리한다. 장비에 따라 기본 미리보기 디코딩이 불안정하면 `--software-decode` 옵션을 사용한다. 이 옵션은 export 인코더 설정과 독립적이다.

영상별 최신 프레임만 유지하고 전체 영상을 메모리에 누적하지 않는다. 영상 제거, 프로젝트 교체, 앱 종료 시 플레이어·프레임·자식 프로세스·작업 임시 파일을 정리한다. 실패한 항목과 원인을 표시하고 UI가 멈추지 않게 한다.

### 코드와 개발 명령

들여쓰기는 4칸, 함수·변수는 `snake_case`, 클래스는 `PascalCase`를 사용한다. 공개 인터페이스에는 타입 힌트를 붙인다. 관련 책임은 작은 모듈로 묶고 UI에 기능을 집중시키거나 불필요한 공통 추상화를 추가하지 않는다.

Python 3.12 가상환경에서 아래 명령을 사용한다. FFmpeg 준비 절차와 검증한 버전·체크섬은 [준비 안내](../vendor/ffmpeg/README.md)에 기록한다.

```powershell
python -m pip install -c constraints.txt -e ".[dev]"
powershell -ExecutionPolicy Bypass -File scripts/setup_ffmpeg.ps1
python -m videos_multi_view
python -m pytest
python -m ruff check .
python -m ruff format --check .
python -m PyInstaller VideoMultiView.spec
```

### 단일 EXE 빌드

단일 EXE 명령은 유지하며, `scripts/build_portable.ps1`로 폴더형 번들과 ZIP도 생성한다. 최종 사용자는 ZIP 전체를 압축 해제하고 EXE를 실행한다. Python·FFmpeg 설치는 빌드 담당자의 개발 환경에서만 필요하다. 포터블 ZIP의 외부 공개에는 [라이선스 자료 준비](LICENSING.md)가 별도로 필요하다.

Windows x64 환경에서 `VideoMultiView.spec`에 onefile·windowed 설정을 기록하고 Qt 플러그인, 재생에 필요한 라이브러리, FFmpeg·FFprobe 실행 파일을 포함한다. 최종 앱은 실행 PC의 Python이나 PATH에 의존하지 않는다.

PyInstaller 단일 EXE는 실행 시 내부 리소스를 임시 경로에 해제한다. 번들 리소스 위치와 프로젝트·export 등 사용자 저장 위치를 분리하고, 사용자 파일을 번들 임시 경로에 저장하지 않는다. 패키징 검증은 폴더형 번들에서 의존성을 확인한 뒤 단일 EXE로 수행한다. [PyInstaller 문서](https://pyinstaller.org/en/stable/operating-mode.html)

### 언어 전환

`Language / 언어` 메뉴에서 한국어·영어를 즉시 전환한다. 설정은 `QSettings`에 저장하고 JSON 프로젝트와 분리한다. CLI `--language ko|en`은 이번 실행만 변경한다. 메뉴·설정·대화상자·도움말을 번역하며 사용자 이름표·경로·매크로·직렬화한 enum 값은 그대로 유지한다. 재생·분석·export를 재시작하지 않는다.

문구 조회는 Qt와 입출력에 의존하지 않는 `i18n.py`와 `translations.py`가 맡는다. UI의 명시적 text binding만 갱신하고, 언어 저장과 시스템 UI 언어 판정은 `application/language.py`가 맡는다. Qt 기본 대화상자에는 번들에 포함한 `qtbase_ko.qm`을 사용한다. 외부 FFmpeg·운영체제 오류의 원문은 번역하지 않는다.

## 4. 구현 순서와 완료 기준

| 단계 | 구현 내용 | 단계 완료 기준 |
|---|---|---|
| 1. 기본 UI·재생 | 패키지·개발 도구 구성, 영상 추가·삭제·순서 변경, 자동 그리드 | 제공 영상 두 개를 불러와 비율을 유지하며 함께 재생한다. |
| 2. 시간 동기화 | 공통 타임라인, 오프셋, 길이 차이, 오디오 선택 | 탐색·재생·종료에서 동일한 시간 규칙을 적용한다. |
| 3. 디자인·프로젝트 | 그리드·테두리·이름표 편집, JSON 저장·복원, 원본 재연결 | 디자인이 즉시 반영되고 다시 열어도 상태가 유지된다. |
| 4. MP4 export | 공통 장식 렌더링, 비동기 합성, 진행률·취소 | 디자인·시각·오디오가 반영된 MP4를 만들고 실패 시 파일을 보호한다. |
| 5. 성능·빌드 | 9개 영상 검증, 자원 정리 확인, 단일 EXE 빌드 | 외부 Python·FFmpeg 없이 EXE에서 입력 두 개를 열고 MP4를 저장한다. |

문서와 실제 구현이 달라지면 기획문서 및 AGENTS의 구조·명령·검증 기준을 함께 갱신한다. 구현되지 않은 기능이나 실행하지 않은 검증을 완료로 기록하지 않는다.

## 5. 테스트와 최종 인수 기준

### 기존 테스트 영상

다음 정보는 초기 계획 시 Windows 메타데이터에서 확인했다. 구현 시 FFprobe 분석 결과로 코덱·길이·회전 정보를 포함해 다시 확인한다.

| 파일 | 해상도 | FPS | 길이 |
|---|---|---|---|
| `test_assets/탑승영상_자막제거.mp4` | 720×1280 | 24 | 약 10초 |
| `test_assets/탑승영상_출처9민선생_original.mp4` | 480×854 | 30 | 약 10초 |

기존 자산은 수정하지 않는다. 추가 테스트 영상은 테스트 전용 임시 경로에 생성한다. 자동화 테스트는 합성 소형 영상을 사용할 수 있게 하고, 실제 자산을 사용하는 검증은 자산이 없을 때 건너뛴 사실을 명확히 표시한다.

### 자동화·수동 검증

| 영역 | 시나리오와 통과 기준 |
|---|---|
| 레이아웃 | 1·2·3·5·9개 배치, 가로·세로·정사각형 혼합, 빈 셀, 열 수 변경에서 겹침·비율 왜곡이 없다. |
| 시간 계산 | 양수·음수·0 오프셋, 서로 다른 길이에서 시작 전 배경·종료 후 마지막 프레임·전체 길이가 규칙과 일치한다. |
| 프로젝트 | 저장·복원으로 설정이 유지되고, 한글·공백·상대경로 및 누락 원본 재연결을 처리한다. |
| UI | 추가·삭제·순서 변경·탐색·디자인 변경이 반영되며 분석·export 중에도 응답한다. |
| 실제 export | FFprobe로 출력 크기·FPS·길이·오디오를 확인한다. 혼합 FPS와 회전 정보가 있는 입력도 검증한다. |
| 시간 정확도 | 시간 표시 합성 영상으로 안정 재생 시 오차 100ms 이내를 목표로 측정한다. export의 시점 오차는 출력 한 프레임 이내로 검증한다. |
| 디자인 일치 | 같은 시점의 미리보기와 출력 프레임에서 셀·테두리·한글 이름표를 비교한다. 압축에 의한 색상 차이는 허용한다. |
| 오디오 | 기본 무음, 선택 영상 하나의 소리, 오프셋, 오디오 없는 입력, 재생 구간 밖 무음을 확인한다. |
| 오류·취소 | 누락·손상 입력, 쓰기 실패, export 취소에서 원본과 기존 결과물을 보존하고 원인을 표시한다. |
| 자원·성능 | 영상 추가·삭제와 프로젝트 교체 후 자원을 해제한다. 2~9개 혼합 입력의 응답성과 동기 오차를 기준 장비에서 기록한다. |
| 단일 EXE | Python·FFmpeg가 설치되지 않은 Windows 환경에서 EXE를 실행하고 영상 두 개를 불러와 MP4를 저장한다. |

pytest는 시간·좌표·프로젝트 동작, pytest-qt는 UI 상호작용, FFmpeg 통합 테스트는 실제 합성 결과를 검증한다. 코드와 같은 계산을 반복하는 테스트보다 관찰 가능한 결과를 확인한다. 수치 커버리지 기준은 두지 않으며 테스트 파일은 `test_*.py`, 함수는 `test_*`로 명명한다.

성능 보고에는 Windows 버전, CPU·GPU·메모리, 입력 수·해상도·FPS, 동기 오차를 기록한다. 9개 고해상도 영상의 실시간 성능은 측정 결과로 판단한다. 모든 단계가 완료되고 독립 실행 환경에서 최종 인수 시나리오가 통과해야 첫 버전 구현 완료로 판단한다.
